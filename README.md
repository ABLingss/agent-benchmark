# Agent Benchmark · 尔绮 AI Coding 现场题

两道可以直接发放的题，每题建议20分钟。候选人使用自己开发的Agent；允许查资料、修改提示词、查看代码与运行结果。重点是可运行、可验证的交付。

| 题目 | 领取入口 | 起点 | 重点 |
| --- | --- | --- | --- |
| 真实推理网关的缓存亲和路由 | [gateway/TASK.md](gateway/TASK.md) | 已有真实HTTP代理与轮询 | 理解已有代码、调度取舍、异常与并发 |
| 可实际使用的点餐结算页 | [frontend/TASK.md](frontend/TASK.md) | HTML入口、固定商品数据 | 交互、金额、持久化、导出、响应式与视觉 |

题目根据公开笔经场景重新制定，不冒称公司官方试卷。[来源与选题](SOURCES.md)区分了候选人自述、二次整理和本项目改编内容。

## 考前准备

- 安装Git、Python 3.10+；前端自动测试另需Node.js 20+与Playwright浏览器，提前按各题README安装。
- 网关题由面试官提前提供可访问的真实兼容后端、模型名与必要凭据，检查一次实际联通。仓库不附模型、密钥或假推理服务。自动测试可独立核验HTTP转发和路由契约。
- 前端应用本身只需Python静态服务与浏览器，导出的是实际下载文件，不依赖业务后端或真实支付。
- 两题均有公开验收。起始版本尚未实现新需求，验收失败是预期；不要把它误认为环境故障。

## 推荐发放方式

1. 面试官指定统一起点commit或tag（如 `exam-v1`），所有人从相同版本开始。
2. 候选人克隆本仓库，在自己的副本创建个人分支；正式开始时再领取题目。若需防止提前准备，先用仓库做环境预检，开考再由面试官公布题面。
3. 交付修改后的仓库commit，以及简短说明：做了什么、如何运行、实际验证结果、遗留问题。允许有失败，但不得伪造验证结果。
4. 为避免互相看到答案，候选人将提交推送到**自己的私有仓库**并邀请面试官；不要在这个公共题库里直接提交含答案的公开PR。
5. 隐藏测试与参考实现由面试官在独立私有位置保存，不放在本仓库的其他分支、tag、提交历史或Actions产物里。

仓库公开后题面也公开，tag只能固定版本，不能保密。正式计时前不要让候选人的Agent读到面试官目录。两题是不同能力维度，不宣称难度等价；横向比较时给所有候选人相同题目、时长和环境。

## 评价原则

网关以功能与真实转发证据为主，前端在功能测试之外评审可用性与视觉。都观察Agent如何理解需求、控制修改、验证和修复；不按提示词长度、代码数量、工具数量或是否开启子代理给分。

实际人工限时难度仍需现场校准，本项目不把参考实现通过测试当作“所有候选人20分钟必能完成”的证明。
