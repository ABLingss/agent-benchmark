# 题二：做一个真正能用的点餐结算页

时间20分钟，使用自己的 Agent 完成页面，视觉布局自由设计。

从本目录 `index.html` 开始，读取 `menu.json`，完成可刷新保留、能导出订单文件的前端应用。使用HTML/CSS/JavaScript，不依赖CDN、外部图片或在线服务。

## 四个验收标准

**1. 点餐闭环。** 展示六个商品、名称和价格；能加入清单、修改数量、删除商品、清空清单。空清单有提示。数量为1–99整数，非法输入失焦时恢复此前有效值，不能产生负价或NaN。

**2. 金额真实。** 所有运算以整数“分”为单位；小计是各单价×数量之和。商品小计满4000分减800分，不叠加；配送费300分，商品小计满5000分免配送费，门槛均按优惠前小计判断。空清单所有金额为0。应付=小计−优惠+配送费。金额显示两位小数。

**3. 能留下结果。** 刷新后保留清单，存储key为 `agent-benchmark-cart-v1`；存储内容损坏时能恢复到可操作的空清单。非空时“导出订单”下载真实JSON文件，含 `items` 数组（id、name、unitPrice、quantity、lineTotal）与整数 `subtotal`、`discount`、`delivery`、`total`。空清单禁用导出。导出不清空现有清单。

**4. 页面可用。** 1440px桌面和375px手机宽度都能正常操作，无横向溢出、遮挡；按钮与数量输入有可理解的标签和键盘焦点。布局、层次、反馈与视觉完成度由人工评审，不按“长得像参考图”评分。

## 为自动验收约定的标记

标记仅用于定位，不限制布局或CSS。需要保留：

| 元素 | 约定 |
| --- | --- |
| 每个商品容器 | `data-testid="product-rice"` 等，后缀为menu中的id |
| 商品内添加按钮 | 可访问名称 `加入清单` |
| 每条清单容器 | `data-testid="cart-rice"` 等 |
| 清单内数量输入 | `type="number"`，可访问名称 `数量` |
| 清单内删除按钮 | 可访问名称 `删除` |
| 四项金额文本 | `data-testid="subtotal"`、`discount`、`delivery`、`total` |
| 清空按钮 | 可访问名称 `清空清单` |
| 导出按钮 | `data-testid="export-order"`，名称 `导出订单` |

金额标记的文本只放金额本身，可带货币符号；各商品单位价格也必须展示。测试将实际点击、输入、刷新、下载，不接受硬编码几个例子。
